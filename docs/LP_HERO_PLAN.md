# LP ヒーロー刷新 実装計画（2026-07-28）

対象: `/lp/moyougae-simulation`（現行の唯一のLP）／変更ファイルは `api/_site.py` の
`landing_html()` 周辺と `docs/`。ブランチ `feature/lp-hero`。

## 0. 設計思想（この計画の判断基準）

このLPはブランドサイトではなく、検索から来た人の悩みに答えてアプリを使わせる実用ページ。
**二層構造**を守る。

- **上層（ファーストビュー）＝ 世界観**: 大胆な余白と大きなビジュアルで惹きつける
- **下層（スクロール後）＝ 実用**: 本文とFAQで悩みに答え、SEO評価を得る

したがって「余白で語る」ために本文を削ることはしない。**削るのはヒーローのリードだけ**で、
本文3セクション・FAQ3問は一字も減らさない（リードの内容はセクション01とほぼ重複しており、
短縮しても페ージ全体の情報量は落ちない）。

## 1. ヒーローのビジュアル方針

### 1-1. 画像の主役を「変わる前のふつうの部屋」にする

H1「集めた画像は、自分の部屋じゃない」に対し、完成された北欧の理想部屋を出すのは矛盾する。
**「あなたのその部屋を変えられる」**と伝わる画像に差し替える。

現画像（`moyougae-simulation-hero.webp`）の所見: 白〜オフホワイトの壁＋ライトオーク、
細脚のローボード、木製フレームのアームチェア、テラコッタのプフ＋セージのクッション、
白いシャギーラグ、大判の抽象アート —— **北欧／ナチュラルの完成形**であり差し替え対象。

### 1-2. スロット名は据え置き（＝自動フォールバック）

**スロット名 `<slug>-hero` は変えない。** これにより新画像を置くまでは現画像がそのまま出る。
新画像を同じ名前で上書きすれば自動で切り替わり、LPが空になる瞬間は発生しない。
優先順位（動画 → 写真 → SVGイラスト）も従来どおり維持する。

### 1-3. 必要な画像の仕様

`docs/LP_IMAGE_GUIDE.md` に反映する。フルブリード化にともない推奨実寸を上げる。

| 項目 | 指定 |
|---|---|
| 比率・実寸 | 16:9 / **2400×1350 px**（フルブリードで大画面に耐える幅） |
| 形式・上限 | WebP 推奨 / **400KB以下** |
| 内容 | 特定様式が判別できない・木質/白basedに寄りすぎない・明るく自然光がある・家具は最小限か無し・生活感がありすぎない |
| 構図 | **被写体を中央に寄せる**（モバイルでは object-fit: cover で左右が切られるため） |
| ライセンス | 商用可・帰属表示不要／人物とブランドの写り込み不可／手動DLした静的ファイル（API取得不可） |

## 2. レイアウト刷新

| 項目 | 現在 | 変更後 |
|---|---|---|
| ヒーロー | テキストブロックの下に画像帯（テキストは画像の外） | **フルブリード・画像の上にテキスト**。デスクトップ `78vh`（70〜85vhの中央値）、`max-height:900px` |
| ヒーローのテキスト | eyebrow・H1・リード3文・CTA・注記3項目 | **H1 ＋ リード1〜2文 ＋ CTA1つ ＋「登録不要」のみ**（eyebrowは残す＝小さなラベルで世界観側の要素） |
| 可読性 | — | **暗いグラデーションのオーバーレイを必ず挿入**。デスクトップは横方向、モバイルは縦方向に切り替え |
| スクロール手がかり | なし | ヒーロー下部に**下向き矢印**＋`78vh` により**次セクションが覗く**配置 |
| セクション間余白 | `clamp(56px,8vw,108px)` | **`clamp(72px,10vw,140px)`**（目安100〜140px） |
| H1 | `clamp(26px,5vw,52px)` | **`clamp(30px,6.2vw,68px)`**・字間を広げる。モバイルは縮小して破綻させない |
| ビジュアルのリズム | before/after が本文幅（1080px）内 | **before/after をフルブリード帯に**して「テキスト→大きな画像→テキスト」を作る |

### 2-1. オーバーレイのコントラスト設計

白文字を載せるため、**最悪ケース（真っ白な写真）でも WCAG AA を満たす**濃度にする。

- デスクトップ（横グラデーション）: テキストが乗る左側で **不透明度 .62 以上**
  → 白(255)×0.38 = 97 → 白文字とのコントラスト比 **約6.2:1**（AA基準4.5:1を満たす）
- モバイル（縦グラデーション）: 下側を濃くし、テキスト帯で同等以上を確保

### 2-2. 画像が無いときの扱い

- ヒーロー: SVGイラストにフォールバック。**同じスクリムを掛ける**ので白文字の可読性は保たれる
  （地の色 #F4F2ED に .62 のスクリムでコントラスト比 約9.7:1）
- before/after: 実画像が2枚そろったときだけフルブリード帯にする。**プレースホルダ状態では
  本文幅のまま**にして、画面いっぱいの破線の空箱が出ないようにする

## 3. 禁止事項の遵守方法

| 禁止事項 | 対応 |
|---|---|
| 本文3セクション・FAQ3問の削除/要約 | データを一切触らない。実装後に**機械的に本数・字数を検証** |
| FAQを折りたたむ場合もHTMLにテキストが存在 | **折りたたまない**（現行どおり全文を平置き） |
| 文字の画像化 | 画像化しない。H1もテキストのまま（`_phrase()` の span 分割のみ） |
| アニメーション過多 | フェードアップと矢印の微動のみ。`prefers-reduced-motion` で無効化 |
| 重いフレームワーク | 追加なし。インラインCSS＋約40行の素のJSのみ |
| UGC/投稿/公開/共有の訴求 | 文言を追加しない。実装後に禁止語を機械チェック |

## 4. 不変を保証するもの（実装後に機械検証する）

`title` / `meta description` / `canonical` / OGP / JSON-LD（WebPage・FAQPage）/
アプリ導線5箇所（`?ref=lp-moyougae-simulation`）/ 楽天クレジット /
アフィリエイト（PR）表記 / 法務リンク3本 / GA4注入。

## 5. 検証計画

1. **数値検証**: 本文セクション数・本文総字数・FAQ設問数・FAQ回答総字数・JSON-LD種別・
   FAQPage設問数・導線数・禁止語の出現数を、変更前（main）と機械比較
2. **レイアウト**: headless Edge で デスクトップ1440px と 実ビューポート 360/390/430px
   （同一オリジンiframe。Edgeは `--window-size` を約492pxで下限クランプするため）
   → 横スクロールなし・文字可読・ヒーロー高さが70〜85vhに収まることを確認
3. **CLS**: 画像あり／なしでヒーロー以下のセクション位置が動かないことを確認
4. **フォーカス可視**: キーボード操作でCTA・スクロール矢印にフォーカスリングが出ること
5. **画像未配置**: 空のアセットディレクトリでレンダリングして崩れないこと
