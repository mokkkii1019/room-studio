# LP汎用化レポート — URL・メタ情報・本文の整合（2026-07-28）

## 0. 背景

LPを1枚に集約し、内容を北欧特化から汎用（Room Studio全般）に変更した結果、
URLが `/lp/hokuo-interior` のままで中身と不一致になっていた。この不整合を解消する。

---

## 🔴 GA4を見る人への記録：2026-07-28 に ref が変わりました

アプリ導線の計測パラメータが、この日を境に変わっています。**GA4でLP経由の流入を
見るときは、日付をまたぐと別の値になる**ため注意してください。

| | 値 |
|---|---|
| 2026-07-28 **より前** | `?ref=lp-hokuo-interior` |
| 2026-07-28 **以降** | `?ref=lp-moyougae-simulation` |

**なぜ変えたか**: `ref` は `/?ref=lp-<slug>` という既存規約でslugに追従する。
LPの流入データがまだほとんど蓄積されていない時期であり、連続性が切れる損失より
規約の一貫性を保つ利益のほうが大きいと判断した（運営判断）。

過去分と合算したい場合は、GA4 で `lp-hokuo-interior` と `lp-moyougae-simulation`
の両方を対象にすること。なお **URLの301は連続性が保たれる**（下記）ので、
検索評価への影響とこの計測キーの断絶は別物である点に注意。

## 1. URLの変更

```
旧: /lp/hokuo-interior
新: /lp/moyougae-simulation
```

**選定理由**: 「模様替え シミュレーション」という高インテントな検索語に直接一致し、
既存slug（`chintai-kabe-makeover` 等）のローマ字慣習とも揃う。家具・床壁・雑貨を
すべて含むアプリの価値を一語で表せ、本文を将来変えても陳腐化しにくい。

canonical / og:url / WebPage JSON-LD の url はいずれもslug由来なので自動追従。

## 2. 301リダイレクト（連鎖なしの1段に統一）

旧4URLすべてを**新URLへ直接**向けた。旧3LPの行き先も `hokuo-interior` から
張り替えているため、`301 → 301 → 200` の連鎖は発生しない。

```
/lp/hokuo-interior           → 301 → /lp/moyougae-simulation → 200
/lp/6jo-hitorigurashi-layout → 301 → /lp/moyougae-simulation → 200
/lp/hitorigurashi-sofa       → 301 → /lp/moyougae-simulation → 200
/lp/chintai-kabe-makeover    → 301 → /lp/moyougae-simulation → 200
/lp/（未知のslug）           → 404
```

`LP_REDIRECTS` に「次にリネームするときも全エントリを張り替える（hopを足さない）」
方針をコメントで明記した。

## 7. 📋 Search Console での作業手順（運営者が手動で行う）

URLを変更したので、検索エンジンへの通知が必要です。**以下はコード側では代行できません。
デプロイが本番に反映されたことを確認してから**、運営者が Search Console で実施してください。

前提: [Google Search Console](https://search.google.com/search-console) に
`roomstudio.jp` のプロパティが登録済みであること。未登録なら先にプロパティを追加し、
所有権確認（DNS または HTML タグ）を済ませてください。

### 7-1. sitemap.xml を再送信する

新URLをできるだけ早く見つけてもらうための作業です。

1. Search Console 左メニューの **「インデックス作成」→「サイトマップ」** を開く
2. 「新しいサイトマップの追加」に **`sitemap.xml`** と入力し「送信」
   （すでに送信済みでも、**同じURLをもう一度送信すれば再クロールのきっかけになります**）
3. 数分〜数時間後、ステータスが「成功しました」／検出されたURL数が **5** になることを確認
   （トップ・運営者情報・プライバシー・特商法・LP1枚）
4. 「検出されたURL」を開き、`/lp/moyougae-simulation` が含まれ、
   **旧URLが載っていない**ことを確認する

### 7-2. 新URLのインデックス登録をリクエストする

サイトマップ送信だけだと反映が遅いことがあるため、個別に依頼します。

1. Search Console 上部の **URL検査** ボックスに
   `https://roomstudio.jp/lp/moyougae-simulation` を貼り付けて Enter
2. 「URL が Google に登録されていません」と出る想定。**「インデックス登録をリクエスト」** を押す
3. 「リクエストを送信しました」と出れば完了（**1日1URLあたりの回数制限があるので連打しない**）
4. 数日後に同じURL検査で「URL は Google に登録されています」に変われば成功

### 7-3. 旧URLは「削除リクエスト」しないこと ⚠️

**旧4URL（`hokuo-interior` ほか3本）に対して、削除リクエストは送らないでください。**

理由: 旧URLには **301リダイレクトを設定済み**です。301は Google に対して
「このページは恒久的にここへ移った」と伝える正規の手段で、**旧URLに溜まった評価は
リダイレクト先へ引き継がれます**。Google は次回クロール時に301を読み取り、
インデックスを自動的に新URLへ置き換えます。運営側の操作は不要です。

ここで「削除ツール」を使うと、**評価の引き継ぎが完了する前に旧URLが検索結果から
消され、301をたどる機会そのものを失いかねません**。削除ツールは本来
「消したいのに消えない情報を緊急で隠す」ためのもので、URL移転に使う道具ではありません。

やること: **何もせず待つ**。気になる場合のみ、URL検査で旧URLを調べて
「ページのリダイレクト」と表示されていること（＝301が正しく認識されている）を確認すれば十分です。
インデックスの置き換えには通常**数日〜数週間**かかります。

### 7-4. 反映後に見ておくとよいもの

- **「インデックス作成」→「ページ」**: 「ページにリダイレクトがあります」に旧4URLが
  移動していけば正常（エラーではありません）
- **検索パフォーマンス**: 旧URLの表示回数が減り、新URLが立ち上がる形になります。
  合算して見たい場合は §「GA4を見る人への記録」と同様、移行期は2URL分を足して評価してください
