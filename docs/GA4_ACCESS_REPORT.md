  `docs/MEASUREMENT.md` §6-1 の「UTMはコード変更なしで機能する」という結論と矛盾しない。

| 観測 | 意味 |
|---|---|

**★ 副産物: フィルタ「有効」時のデータは、処理前に「テスト」へ切り替えれば救える。**
リアルタイムに出なかった `probe-20260814e` のセッションが、標準レポートには残っていた。

> **実ユーザーへの影響はない。** 一般の訪問者は `rs_notrack` を持たず、IPも `/32` に一致しない。
> 影響範囲は「運営自身のスマホでテストできるか」だけ。

### 11-7. 旧ドメインの308リダイレクト — 実装した（§10-7 の実装分）

`room-studio-fawn.vercel.app` は 2026-08-15 時点でも **200 を返し、`const GA4_INTERNAL=1` と
`G-685NHQ7432` を注入している**（実測）。`api/index.py` に、既知の旧ホストだけを
`SITE_BASE_URL` のホストへ **308** で寄せるミドルウェアを追加した。

| 決めたこと | 理由 |
|---|---|
| **308**（301/302 ではない） | method と body を保持する。旧ドメイン宛ての POST（`/collect`・`/bgcut`）が GET に化けて 405 になるのを防ぐ |
| path と query をそのまま持っていく | 落とすと `utm_*` が消えて (direct)/(none) になる（退役LPの301と同じ理由・指示031 A3） |
| **既知の旧ホストだけ**（`LEGACY_HOSTS`、既定 `room-studio-fawn.vercel.app`） | 「本番ドメイン以外は全部」にすると**プレビュー配信が本番へ飛んで動作確認ができなくなる**。プレビューの計測混入は Vercel の環境変数を Production 限定にして止める話 |
| `SITE_BASE_URL` 未設定なら何もしない | 未設定時の既定値は旧ドメイン自身。素直に書くと**自分から自分へ308する無限ループ**になる |
| ミドルウェアを一番先に登録 | Starlette は先に登録したものが外側。アプリ本体を1バイトも配らずに折り返す＝GA4タグ入りHTMLが出ない |

手元の検証（`fastapi.testclient`、SITE_BASE_URL=`https://roomstudio.jp`）:

| ホスト | パス | 結果 |
|---|---|---|
| `room-studio-fawn.vercel.app` | `/lp/x?utm_source=x&utm_medium=social&utm_campaign=a-b_c` | 308 → `https://roomstudio.jp/lp/x?utm_source=...`（**クエリ保持**） |
| 同上（大文字・`:443`付き） | `/health` | 308 |
| `roomstudio.jp` | `/health` | 200（素通り） |
| `room-studio-qjwmnhc5d-....vercel.app`（プレビュー） | `/health` | **200（素通り）** |
| `localhost:8000` | `/health` | 200（素通り） |
| SITE_BASE_URL 未設定 + 旧ホスト | `/health` | **200（ループしない）** |

**本番反映後の実測（2026-08-15・push から約2分で反映）— 全項目 期待どおり:**

| 確認 | 結果 |
|---|---|
| 旧ドメイン トップ | `308` → `Location: https://roomstudio.jp/` |
| 旧ドメイン LP + `utm_*` 3つ | `308` → `.../lp/moyougae-simulation?utm_source=x&utm_medium=social&utm_campaign=probe-20260815a`（**クエリ完全保持**） |
| 旧ドメインへ **POST** `/collect` | `308` → `https://roomstudio.jp/collect`（method を保持） |
| 旧ドメインをリダイレクト追跡 | 最終到達 `https://roomstudio.jp/` ・ `200`（1ホップで完了・ループなし） |
| 本番 `/` `/lp/...` `/health` | すべて `200`（巻き込み事故なし） |
| 本番のタグ注入 | `const GA4_INTERNAL=1` / `var i=o&&true`（**変化なし**） |

```powershell
curl.exe -sI https://room-studio-fawn.vercel.app/ | Select-String "^HTTP|^location"
curl.exe -sI "https://room-studio-fawn.vercel.app/lp/moyougae-simulation?utm_source=x" | Select-String "^location"
curl.exe -sL -o NUL -w "final=%{url_effective}  code=%{http_code}`n" https://room-studio-fawn.vercel.app/

# ★ 本番側（リダイレクトされない方）を確かめるときは -I を使わないこと
curl.exe -s -o NUL -w "%{http_code}`n" https://roomstudio.jp/     # 期待 200
```

> **⚠️ `curl -I`（HEAD）は本番ドメインだと 405 が返る。これは正常で、今回の変更とは無関係。**
> FastAPI は GET のルートに HEAD を自動で足さない（Starlette 素の `Route` は足すが、
> `APIRoute` は足さない）ので、`/` も `/health` も HEAD には 405 を返す — 変更前からそう。
> 旧ドメイン側で `-I` が効くのは、**ルーティングに届く前にミドルウェアが折り返している**から。
> 本番側の生死確認は `-s -o NUL -w "%{http_code}"`（＝GET）で見ること。
> HEAD で外形監視を設定すると全部 405 に見えるので、そこだけ注意。
