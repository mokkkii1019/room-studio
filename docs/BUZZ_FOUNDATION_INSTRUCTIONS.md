# 作業指示書:バズ受け皿と拡散素材の自動化基盤

**対象**: Claude Code(このリポジトリで作業する実行エージェント)
**目的**: SNS拡散(ショート動画・X)に耐える「受け皿」と、拡散素材を自動生産する「工場」を実装する。具体的には次の3機能。
1. **スマホ30秒ミニ体験** — スマホ流入者が即座に価値を体験できる超軽量デモ
2. **自動デモモード** — 画面録画するだけで動画素材が撮れる自動再生機能
3. **共有画像の自動生成** — before/after合成画像をワンクリックで書き出す

**背景(設計判断の根拠)**: ショート動画からの流入は大半がスマホだが、Room Studio本体は処理が重くPC前提。このままバズを起こすと「重くて使えず即離脱」となり、流入がすべて無駄になる。本作業はその穴を塞ぐことが最優先。

**前提**: 単一HTML(`room-studio.html`)+ Vercel FastAPI のステートレス構成。Supabase/DB/認証は追加しない。LP群は `api/_site.py` がサーバー生成し `roomstudio.jp/lp/...` で配信。既存の楽天API連携・GA4・アフィリエイト導線は稼働中。

---

## 0. 絶対に守るルール

1. **既存のアプリ本体(PC版フル機能)の挙動を壊さない。** 新機能は追加であって、既存フローの置き換えではない。
2. **楽天API連携・`affiliateUrl`・`/imgproxy` 許可ホスト・`RAKUTEN_*` 環境変数に手を触れない。** 収益導線は不変。
3. **UGC・投稿公開・共有ギャラリー機能は実装しない**(従来方針)。本書の「共有画像生成」は**ユーザー自身がSNSに投稿するための画像をローカルに書き出す機能**であり、サーバーに保存・公開する機能ではない。
4. **重いフレームワークを導入しない。** 現構成(素のJS/HTML/CSS + FastAPI)の軽量性を維持。特にミニ体験は徹底的に軽く。
5. **Supabase/DB/認証を追加しない。** 状態は必要最小限をクライアント側で持つ。
6. **秘密情報をハードコードしない。** 環境変数経由を維持。
7. ブランチ `feature/buzz-foundation` を作成。main へ直接コミットしない。マージは運営者が判断。
8. **段階実装**: §1 → §2 → §3 の順に、それぞれ動作確認できる単位でコミットする。§1が最優先(バズ受け皿)。

## 1. スマホ30秒ミニ体験(最優先)

### 目的
SNSからスマホで流入した人に、**3秒以内に表示され、30秒以内に「変わる」体験**をさせ、離脱ではなく記憶と再訪(PCでの本利用)に変換する。

### 仕様
- **URL**: `/try`(または `/lp/try`。既存ルーティング規約に合わせる)。スマホ・PC双方で動くが**モバイル最適化を最優先**。
- **サンプル部屋のプリロード**: 運営が用意した部屋画像(§4のアセット規約に従う)を最初から読み込んだ状態で表示。ユーザーは写真をアップロードせずに即体験できる。
- **操作は極限まで絞る**: フル機能を持ち込まない。以下だけ。
  - **壁の色を変える**: 色スウォッチ4〜6個をタップで即切替(北欧トーン・グレージュ・淡いグリーン等、既存の表面色機能を流用)
  - **床の色/素材を変える**(可能なら。重ければ壁のみで可)
  - **家具を1〜2点、置く/外す**トグル(事前に配置座標を決めておいた固定配置でよい。自由なドラッグ操作は不要)
  - **before/after 切替**(元の状態に戻すボタン)
- **性能目標**: モバイル回線で**初回表示3秒以内**を目指す。サンプル画像は圧縮、必要最小のJSのみ、フル機能のコードを読み込まない(可能なら本体とは別の軽量ページとして実装)。
- **導線(重要)**:
  - 体験後に「**自分の部屋の写真でやってみる**」CTA → PC版フル機能へ(スマホの場合は「PCで開くとフル機能が使えます」と案内 + **URLをコピー/ブックマークを促す**UI)
  - 使用した家具の**商品リンク(既存のアフィリエイト導線)**を1〜2件表示。ここが収益接点。
  - 関連LPへのリンク
- **計測**: GA4に専用イベントを送る(例: `try_view`, `try_color_change`, `try_cta_click`)。既存のGA4注入・`/track` の仕組みに合わせる。UTM付き流入がここに着地する前提。
- **OGP**: `/try` に専用のOGP画像・タイトル・descriptionを設定(SNSでリンクが映えるように)。

## 2. 自動デモモード(動画素材の自動生産)

### 目的
ショート動画用の素材撮影を自動化する。運営は**画面録画を開始してURLを開くだけ**で、「変身」シーンが自動再生される状態にする。手動操作の撮影をなくす。

### 仕様
- **URL**: `/demo`(またはクエリ `?demo=1`)。運営専用の想定だが認証は不要(URLを知っている人だけが使う程度でよい。sitemap/robotsからは除外し、`noindex` を付与)。
- **自動再生シーケンス**: ページを開くと、以下が自動で順次実行される。
  1. サンプル部屋を表示(before状態を数秒静止)
  2. 家具が順に配置される(アニメーション/段階表示)
  3. 壁・床の色が切り替わる(2〜3パターンを順に)
  4. after状態で静止
  5. (任意)ループ再生
- **タイミング調整**: 全体で **15秒 / 30秒** の2モードを用意(`?len=15` `?len=30` 等)。ショート動画の尺に合わせる。
- **画面の清潔さ**: 録画に映り込むUI(ツールバー、ボタン、カーソル等)を隠す `?clean=1` オプションを用意。**縦型(9:16)表示モード**も用意する(`?ratio=9x16`)。ショート動画は縦型が主戦場のため、これは必須。
- **プリセット指定**: どのサンプル部屋・どのテイストで再生するかをクエリで選べるようにする(例 `?preset=hokuo`)。テイスト違いで複数の動画を量産できるように。
- **`prefers-reduced-motion` は尊重**するが、demo モードは意図的なアニメーションのため、明示的にdemoを開いた場合は再生してよい。

## 3. 共有画像の自動生成(静止画素材の自動生産)

### 目的
Pinterest・X・サムネイル用の**before/after合成画像**を、ワンクリックで書き出せるようにする。手作業のスクショ・画像編集をなくす。

### 仕様
- アプリ本体(または `/demo`)に「**共有画像を書き出す**」ボタンを追加。押すと、現在の状態から画像を生成して**ローカルにダウンロード**する(サーバー保存・公開はしない)。
- **出力パターン**(選択可、既定は横並び):
  - **before/after 横並び**(1:1 または 4:3。Pinterest向けに **2:3 縦長**も選べると理想)
  - **after単体**(16:9。X・サムネイル向け)
- **合成内容**: before画像とafter画像を並べ、控えめなラベル(Before / After)と、隅に小さく `roomstudio.jp` のウォーターマーク(ブランド想起+流入誘導)。デザインは既存トークン(オフホワイト/テラコッタ/セージ、`LP_REDESIGN_INSTRUCTIONS.md` 準拠)に合わせ、上質に。
- **実装方式**: クライアント側の Canvas で合成し `toBlob`→ダウンロード。サーバー負荷ゼロ、追加依存なしを優先。
- **注意**: 生成画像に**楽天の商品画像がそのまま大きく写り込む形での再配布**にならないよう配慮する。合成対象は「アプリ画面上のレンダリング結果」であり、商品カタログ画像の切り出し配布ではないことを実装コメントに明記。判断に迷う場合は、商品画像を含まない部屋のレンダリング部分のみを対象にする。

## 4. サンプル部屋アセットの規約

- サンプル部屋画像は運営が用意し、既存の `lp-assets/` 相当の規約に従って配置する(既存規約を優先。無ければ `lp-assets/try-room-<n>` 等)。
- Claude Code は**プレースホルダで実装**し、実ファイル未配置でも動作・レイアウトが崩れないようにする。
- 必要なアセットの一覧(用途・推奨実寸・比率・上限KB・中身の指示)を `docs/BUZZ_ASSET_GUIDE.md` に明記する。運営はこれを見て画像を用意する。
- 注意書きとして、フリー素材を使う場合は**商用可・帰属不要、人物とブランドの写り込み不可、手動ダウンロード**である旨を記載する。

## 5. 進め方と完了条件

1. `docs/BUZZ_FOUNDATION_PLAN.md` に計画を書き、本書をチェックボックス化。運営への確認は挟まず、曖昧点は本書・`CURRENT_SPEC.md`・既存実装に沿って合理的に判断し記録する。
2. **§1(スマホ体験)を最初に完成させ、単体で確認できる状態にする。** 次に §2、§3。各段階でコミット。
3. **品質ゲート(完了の定義)**:
   - `/try` がモバイル幅で崩れず、色替えが即反応し、体感で軽い(重いJSを読み込んでいない)
   - `/try` に商品リンク(アフィリエイト導線)とPC版への誘導、GA4イベントがある
   - `/demo` が自動再生し、15秒/30秒・縦型9:16・clean表示が機能する。`noindex` かつ sitemap 非掲載
   - 共有画像の書き出しが動作し、生成画像が破綻しない(文字が切れない、比率が正しい)
   - 既存のPC版フル機能・楽天連携・アフィリンク・LP群・GA4が不変(リグレッションなし)
   - `docs/BUZZ_ASSET_GUIDE.md` に運営が用意すべき画像が明記されている
4. 完了後 `docs/BUZZ_FOUNDATION_REPORT.md` に、実装内容・各URL・スクリーンショット・運営が用意すべきアセット一覧・録画手順(どのURLをどう開けば何秒の素材が撮れるか)をまとめる。
