# バズ基盤：運営が用意する画像ガイド

`docs/BUZZ_FOUNDATION_INSTRUCTIONS.md` の実装で必要になる画像の一覧と条件です。
置き場所・命名・配信の仕組みは既存のLP画像と同じ（`lp-assets/` に置くだけ）。

- 置き場所: リポジトリ直下の **`lp-assets/`**
- 配信URL: `https://roomstudio.jp/lp-assets/<ファイル名>`
- **対応形式**: `.webp`（推奨）/ `.jpg` / `.jpeg` / `.png` / `.avif`。**拡張子は自動判別**
- 置いたら `git add lp-assets/ && commit && push`（main反映で本番に出る）

## 📛 ファイル名の規約（必読）

**`lp-assets/` に置くファイル名は半角英数字にしてください。**
使える文字は `A-Z a-z 0-9 . _ -` だけです。

日本語・全角・スペースを含む名前は**配信できません**。`/lp-assets/{name}` のルートは
パス安全のためファイル名を検査しており、条件を外れると **404** になります
（実装は `api/_site.py` の `_lp_asset_path()`）。ページ側はファイルが無いものとして
扱うため、**画像が出ないだけでエラーにはならず、気づきにくい**のが厄介です。

### 渡し方は2通り。どちらでも構いません

| | 運営がやること | こちらがやること |
|---|---|---|
| **A. 原本を渡す（推奨）** | 無加工の原本を **`docs/src/`** に置く。**ファイル名は日本語のままで構いません** | 変換・リサイズ・トリミング・命名をこちらで行い、`lp-assets/` に配置 |
| **B. 完成品を置く** | 指定の実寸・比率・容量に加工し、**半角英数字の指定ファイル名**で `lp-assets/` に置く | なし |

`docs/` は `.vercelignore` の対象なので、大きい原本を置いても本番の関数サイズには影響しません。
原本は `.gitignore` の例外に入れてあり、リポジトリで versioning されます
（あとから別サイズを切り直すときの元データとして必要なため）。

**未配置でも `/try` は動きます。**サンプル写真が無い間は、コードが簡易的な部屋
（壁・床・窓）を描いて同じように色を変えられます。写真を置くと自動で差し替わります。

## ⚠️ ライセンス（LP画像と同じ・必読）

- ✅ **商用利用可・帰属表示不要**の素材のみ（例: Unsplash / Pexels の標準ライセンス）
- 🚫 **人物が写った写真は使わない**（モデルリリースが保証されないため）
- 🚫 **ブランドロゴ・商標・他社商品が明確に写った写真は使わない**
- 🚫 **API経由で自動取得しない**。**手動でダウンロードした静的ファイル**を置く

## 🤖 AI生成素材の可否（必読・2026-07-29 制定）

判断の軸は **「どこに置くか」ではなく「その素材が何を主張して見えるか」** です。
置き場所で線を引くと、ヒーローに置いた製品デモ風の映像が素通りしてしまうため、
**見た人がどう読むか**で判断します。

| 文脈 | 素材が主張していること | AI生成 |
|---|---|---|
| **製品の出力・動作を示す文脈**（before/after・`/try`・`/demo`） | 「Room Studio を使うとこうなる」 | 🚫 **不可**。**実際の Room Studio の出力のみ**を使う |
| **世界観・イメージを示す文脈**（ヒーロー・装飾） | 「こういう空気感のサービスです」 | ✅ 可 |

### ⚠️ 後者でも「製品の動作と誤認される素材」は不可

置き場所がヒーローでも、内容が製品デモに見えるなら不可です。

| 例 | 判定 | なぜ |
|---|---|---|
| 素敵な部屋が**ただ映っている**（現行の `moyougae-simulation-hero.webp` がこれ） | ✅ 可 | 完成した部屋の雰囲気を見せているだけで、操作の結果には見えない |
| **空室に家具が入って部屋が完成する**動画 | 🚫 不可 | ヒーローに置いても「このアプリを使うとこうなる」と読まれる |

### この原則の理由

1. **誇大表示の回避** — AI生成の家具は、Room Studio が実際に配置した楽天の実在商品ではありません。
   製品の動作として見せると、できないことをできると示すことになります。
2. **楽天の実在商品を扱う製品としての整合** — before/after の after は
   **必ず Room Studio の実出力**、という従来からの原則（`docs/LP_IMAGE_GUIDE.md`）と揃えます。

### 適用実績

- **2026-07-29**: after 画像を起点に「Before → After → 北欧家具が入る」11秒の動画を生成したが、
  **LPへの配置を見送り**（ヒーロー・before/after スライダー近辺のいずれも）。家具がAI生成で
  実在商品ではなく、上表の「不可」に該当するため。SNS用のイメージ映像として、
  実機能を示す `/demo` の録画と組み合わせて使う想定でローカル保管。
  （技術面でもヒーロー動画規約の 6〜12秒シームレスループを満たしていなかった）

## 1. `/try` のサンプル部屋（最優先・1枚）

`/try` はSNSから来た人が最初に触る画面です。**この部屋の壁と床の色を変える**のが体験の中身なので、
写真の条件が体験の質をほぼ決めます。

### 置き方は2通り。**A を推奨します**

**A. マスター（無加工の元データ）を1枚置く → 派生は実装側で作る（推奨）**

| 項目 | 指定 |
|---|---|
| 置き場所 | **`docs/src/try-room-1-master.jpg`**（`.png` でも可） |
| 実寸 | **無加工・撮って出しの最大サイズのまま**。リサイズも圧縮もしないでください |
| 比率 | **問いません**（縦長でも可） |

`docs/` は `.vercelignore` で本番の配信対象から外れているため、大きいマスターを置いても
本番の関数サイズには影響しません。ここから `/try` 用（3:2）と、必要ならLP用（16:9）の
切り出し・リサイズ・WebP変換を**実装側で行います**。トリミングの判断（どこを残すか）は
面のポリゴン定義と一体なので、まとめて引き受けたほうが破綻しません。

**B. 自分で 3:2 に加工して置く**

| 項目 | 指定 |
|---|---|
| ファイル名 | **`lp-assets/try-room-1`**（拡張子任意） |
| 比率 | **3:2**（横長） |
| 推奨実寸 | **1200×800 px**（大きくしすぎない。下記「実寸を絞る理由」参照） |
| 形式・上限 | WebP 推奨 / **250KB以下** |

### 内容の条件（重要）

| 条件 | 理由 |
|---|---|
| ✅ **壁と床が広く写っている** | 色を変える対象がこの2面。面積が小さいと変化が伝わらない |
| ✅ **家具が少ない** | 家具が多いと壁・床が隠れ、かつ後述のポリゴン定義が難しくなる |
| ✅ **明るい**（自然光が入っている） | 暗い写真は色を変えても違いが出ない |
| ✅ **人物・ブランドの写り込みなし** | 上のライセンス条件 |
| ✅ 壁が**平面で素直に見えている**（極端な斜め・柱・凹凸が少ない） | 面をポリゴンで囲むため |
| ✅ 壁が**複数面（左・正面・右）見えていてもよい** | 面ごとにポリゴンを定義でき、面ごとの光の違いも保たれます |
| ⚠️ 窓・ドアは**あってもよい**が、位置が分かりやすいこと | ポリゴンで避ける必要があるため |

### 実寸を絞る理由

色替えは端末側で1ピクセルずつ計算します。画像が大きいほど低スペック端末で
体感が重くなるため、**1200×800 を上限の目安**にしてください。これ以上大きくしても
スマホの画面では見た目が変わりません。

## 2. `/try` の家具（任意・1点）

「家具を置く／外す」トグルで表示する家具です。**未配置ならシルエットのプレースホルダ**が出るので、
無くても動作します。

| 項目 | 指定 |
|---|---|
| ファイル名 | **`try-furni-1`**（拡張子任意） |
| 形式 | **PNG（背景透過）** 必須 |
| 推奨実寸 | 幅 700px 前後 |
| 上限 | 150KB |
| 内容 | ソファなど**床に置く家具1点**を正面〜斜め前から。影は薄く付いていてよい |

🔴 **楽天から収集した家具の画像は使えません。** `/try` は公開ページなので、
LP画像と同じ理由（楽天ウェブサービス利用規約：目的外利用・再配布・不特定多数と
共有可能な場所への保管の禁止）で不可です。自分で撮影した家具、またはCC0・商用可の
素材を使ってください。

## 3. サンプル部屋の写真 — **確定済み（2026-07-29）**

運営から受領し、`/try` に組み込み済みです。**追加の対応は不要**です。

| | 内容 |
|---|---|
| 受領ファイル | `lp-assets/北欧before.png`（1100×733・PNG・1.31MB） |
| 配信用に変換 | **`lp-assets/try-room-1.webp`**（1100×733・**66KB**・quality 84） |
| マスターの退避先 | **`docs/src/try-room-1-master.png`**（無加工の原本。`docs/` は `.vercelignore` 対象なので本番バンドルには載りません） |

### ⚠️ 受け渡し時の注意（今回ぶつかった点）

**日本語のファイル名は配信できません。** `/lp-assets/{name}` のルートはパス安全のため
ファイル名を `[A-Za-z0-9._-]` に制限しており、`北欧before.png` はこの検査で弾かれて
404 になります。今回はこちらで `try-room-1.webp` に変換・改名しました。
今後は**半角英数字のファイル名**で置いてください（迷ったらマスターを `docs/src/` に
置いていただければ、変換・命名はこちらで行います）。

### 定義したポリゴン座標

写真から実測して `api/_site.py` の `TRY_ROOM` に組み込み済みです。壁は**5枚**に分割
しています（左壁／奥壁の窓左・窓上・窓右／右壁）。奥壁を3枚に割っているのは、
**窓を着色対象から外す**ため（1枚の多角形に穴を開ける代わり）。

読み取り方法:
- **壁と床の境界** — 列ごとに下向きへ走査し「暖色（木床）になる最初の行」を拾って直線を当てた
- **壁と天井の境界** — 白同士で目視できないため、コントラストを強く伸ばして稜線を読んだ
- 定義後、ポリゴンを写真に重ねた画像で当たりを目視確認した

天井は着色対象から除外しています（理由は下記）。
