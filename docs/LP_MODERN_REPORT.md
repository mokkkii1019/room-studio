## 2. 実装メモ

- `_phrase()` — 見出しを 読点 で区切って各句を `display:inline-block` の span に包む。
  日本語は文字間どこでも改行できるため、狭い列で「北欧イン/テリア」のような
  語中改行が出る。inline-block は shrink-to-fit なので**句の間で改行することを優先**し、
  句そのものが列より広ければ内部で折り返す＝**はみ出しは起こらない**。
  `word-break:auto-phrase` も併記してあるが、実測した Edge では効かなかったため、
  どこでも効くこちらを主とした。テキスト内容は変わらないのでクローラからは同一。
- **no-JS でも壊れない**: フェードアップの初期状態（`opacity:0`）とスライダーの
  重ね合わせレイアウトは**すべて `.js ` プレフィックス付き**で書いてある。`.js` は
  head の1行スクリプトが付けるので、JSが無ければ「全部見えている・before/afterは横並び2枚」
  という従来の静的な形になる。
- **既存の画像運用は不変**: `lp-assets/<slug>-hero|before|after`、拡張子自動判別、
  未配置時のSVGフォールバックと `ph: True` のプレースホルダ挙動、`width`/`height`
  明示によるCLS対策、ヒーローのみ `eager`＋`fetchpriority=high` は全部そのまま。
- ヒーローのSVGイラストは新トーンに描き直した（生成りの地＋墨の線画）。
- 既存バグを1つ修正: `ba["ph_b"]` を無条件に参照していたため、`ph` 未指定のLPに
  before/after を両方置くと `KeyError` になっていた。`.get()` に変更し、4LPすべてに
  `ph_b` / `ph_a` の文言を用意した。

## 3. 検証（刷新時・4LPあった時点）

すべて `python` レンダリング＋ headless Edge 実測。

**SEO面（main版と機械的に比較）** — 4LPすべてで
`title` / `description` / `canonical` / OGP全件 / `WebPage` JSON-LD /
**FAQPageの設問・回答** / ページ内リンクURLの集合 が **完全一致**。

**構造・表記** — h1は各LP1個のみ、`_phrase()` を通しても h1 のテキストは元のまま、
`/?ref=lp-<slug>` の計測パラメータ・PR表記・運営者/プライバシー/特商法リンク・
楽天クレジットは全LPに存在。

**画像の状態ごとの挙動**

| 状態 | 結果 |
|---|---|
| 画像ゼロ | ヒーロー=SVGイラスト。before/afterはスライダー用マークアップを一切出さない |
| before/after 2枚 | スライダー化。`cmp-side` 2つ・range入力にaria-label |
| **1枚だけ** | 静的な横並びにフォールバック（中途半端なスライダーにならない）＋欠けた側はプレースホルダ枠 |
| 他LPへの波及 | 北欧に画像を置いても他3LPは変化なし |

**画像属性** — hero `1600x900 eager fetchpriority=high`、before/after `800x600 lazy` を実測確認。

**スライダーが本当に動くか** — range の初期値を 18 にしたページをレンダリングし、
仕切りが 18% の位置に描画されることを確認（JSが死んでいれば 50% のまま）。

**レイアウト（実ビューポート）** — Edge は `--window-size` を約492pxで下限クランプするため、
同一オリジンの iframe に読み込んで **360 / 390 / 430px** の実ビューポートで計測:

| 幅 | 横スクロール | 下部固定CTA |
|---|---|---|
| 360 / 390 / 430 | **なし**（scrollWidth == clientWidth） | 表示される |
| 744 | なし | 表示される |
| 1416 | なし | 非表示（デスクトップ） |

## 4. 3LPの破棄（2026-07-28）

`LANDING_PAGES` から3枚を削除し、北欧LP（`hokuo-interior`）だけを残した。

- **削除**: `6jo-hitorigurashi-layout` / `hitorigurashi-sofa` / `chintai-kabe-makeover`
- 北欧LPの `related`（他3枚への内部リンク）と、他LPから参照されるためだけにあった
  `anchor` キーを削除。関連ページのセクションはリンク先が無くなるので**自動的に出なくなる**
  （`landing_html` は空の `related` を素通りする）。レンダリング側の仕組みは残してあるので、
  将来LPを足せばそのまま復活する。
- `sitemap.xml` は `LANDING_PAGES` 由来なので **8URL → 5URL**（トップ＋法務3＋LP1）に自動で縮む。
- `lp-assets/` に残っていたのは `hokuo-interior-hero.webp` のみ＝**削除すべき画像は無し**。

### ⚠️ 消したURLは404になる

`/lp/6jo-hitorigurashi-layout` など3本は、`landing_html()` が `None` を返し
`api/index.py` / `server.py` のルートが **404** を返す。本番（roomstudio.jp）で公開済み・
インデックス済みのURLなので、検索結果やGA4の参照元から来た人は404に当たる。

意図的な廃止なら404のままでも間違いではない（Googleは404を見て徐々に落とす）が、
**北欧LPへ 301 リダイレクト**すれば、残っている評価と流入をそのまま引き継げる。
必要なら `/lp/{slug}` のルートに「削除済みslug → `/lp/hokuo-interior`」の
マップを1つ足すだけで実装できる（未実装）。

## 5. 旧URLの301リダイレクトとヒーロー動画（追加実装）

### 削除した3LPは404ではなく301に

`_site.LP_REDIRECTS` に「廃止slug → 生存slug」を持たせ、`/lp/{slug}` が
`landing_html()` から `None` を受けたときに **301** を返すようにした（`api/index.py`・
`server.py` の両方）。ループ防止のため、生きているslugと、行き先が存在しないものは
リダイレクトせず404のまま。

```
/lp/6jo-hitorigurashi-layout → 301 → /lp/hokuo-interior → 200
/lp/hitorigurashi-sofa       → 301 → /lp/hokuo-interior → 200
/lp/chintai-kabe-makeover    → 301 → /lp/hokuo-interior → 200
/lp/does-not-exist           → 404
```

### ヒーローを動画にできるようにした

ヒーローの優先順位を **動画 → 写真 → SVGイラスト** に変更。`lp-assets/` に
`<slug>-hero.mp4`（または `.webm`）を置くだけで全面動画になる。

- 装飾目的の背景動画なので `muted` `loop` `playsinline` `autoplay`・コントロール無し・
  `aria-hidden="true"`（操作できないプレイヤーを支援技術に読ませない）。意味は隣のh1/リードが担う
- `poster` には静止画スロットの写真を自動で使う。初回描画・自動再生拒否時・デコード失敗時に出る
- `autoplay` はマークアップ側に置いてあるのでJS無しでも再生される。**省モーション設定の人には
  スクリプトが `pause()`** してポスター表示に落とす
- 画像スロットの解決は今までどおり**画像拡張子のみ**を見るので、`<slug>-hero.mp4` を隣に置いても
  `<slug>-hero` は写真のまま（poster が動画に化けない）

### 配信に Range 対応を追加（動画の前提条件）

このプロジェクトには `vercel.json` が無く、**全リクエストが Python 関数経由**で配信される。
そのままでは動画に2つの問題があるため `_site.lp_asset_range()` を追加した。

1. **iOS Safari は Range を返さないサーバーの `<video>` を再生しない** → 206 Partial Content に対応
2. **Vercel の1レスポンス上限（約4.5MB）** → 開放レンジ（`bytes=0-`）は最大3MBで打ち切って206で返す。
   HTTP的に正当な部分応答なので、上限を超える動画でも再生は継続できる

`416`（範囲外）、`Accept-Ranges`、`Content-Range` も実装済み。既存の `lp_asset()` は
この新関数の薄いラッパにしてあるので `/materials/` 側の挙動は不変。

**検証**: レンジ解析の単体（`bytes=0-` / `10-19` / `-20` / 範囲外 / 不正）9件、
実HTTPでの 200・206・416・`Accept-Ranges`・`Content-Range`、3MB打ち切り、
ヒーローの3段フォールバック（動画/写真/SVG）と `<video>` の属性一式、
実ルートでの301（3本とも `/lp/hokuo-interior` へ、追跡して200）を確認。

⚠️ **未検証**: 環境に ffmpeg が無く**本物の動画ファイルでの再生確認はできていない**。
レイアウト・poster表示・配信（Range）・マークアップは確認済みだが、実際の再生は
動画ファイルを置いたあとに実機（特にiOS Safari）で確認すること。

## 6. 運営者向けの注意

- **画像の準備は今までどおり**。ファイル名・比率・推奨サイズは不変なので書き出し直しは不要。
- ただしスライダーは2枚を重ねるため、**before と after は同じ画角で撮る**ことがより重要。
- 現在のLPは **`/lp/hokuo-interior` の1枚だけ**。`lp-assets/` にあるのは `hokuo-interior-hero.webp`
  の1枚のみで、**before/after はまだ無い**。よってドラッグ比較スライダーは本番ではまだ表示されず、
  破線のプレースホルダ枠が出ている状態。2枚置いた時点で自動でスライダーに変わる。
- 楽天から収集した家具をbefore/afterに写さないルールは従来どおり（`LP_IMAGE_GUIDE.md` §🔴）。
