### 追加の依頼（2026-08-17）— 「画像だけ2倍にしてください」

上の実測で「2倍にすると『詳細』ボタンと『✕』も一緒に2倍になり画像の上辺2割を覆う」と
報告したところ、運営から**「画像だけ2倍にしてください」**。対応済み・本番反映済み。

**やり方:** カードは今までどおり `scale(2)`。画像に重なるUIだけ `scale(.5)` で打ち消して、
見た目の大きさを等倍に保つ。親の `scale(2)` と合成されて等倍で描かれるので**文字はぼやけない**。

| 要素 | 拡大中の扱い |
|---|---|
| サムネ（`canvas.thumb`） | **2倍**（これだけが大きくなる） |
| 「詳細」`.buy` | `scale(.5)`・`transform-origin:top left` |
| 「⤓」`.save` | `scale(.5)`・`top right`。`right:24px→15px`＝**✕ との間隔も等倍**に |
| 「✕」`.del` | `scale(.5)`・`top right` |
| 「＋ 配置」`.add` | 下端の帯（`top:42px; height:16px`）＋ `scale(.5)`・`bottom center`。**`left/right:-50%` で局所幅を2倍にしてから半分に描く**ので、帯は画像の幅いっぱいに出る |
| 切り抜き中のスピナー `.cut-spin` | **transform は使えない**（`@keyframes sp` の回転がアニメーション優先で勝つ）。箱ごと半分にする＝`width/height:6.5px`・`border-width:1px`（`border-box` なので 2倍で 13px・border 2px＝元どおり） |
| 名前 `.nm` / 価格 `.price` | **2倍のまま。** 画像の下にあり画像を隠さないうえ、`text-overflow:ellipsis` で切れている商品名と店名が読めるようになるので、そのほうが得。等倍に戻したい場合は言ってもらう |

打ち消しは **`:hover:not(.nozoom)`** に付けた。ドラッグ中はカードが等倍に戻るので、
打ち消しも一緒に外さないと**UIだけ半分**になる。

#### 実測（ローカル・カードは `makeFurniEl` を実データ相当の item で描かせた10枚）

判定は `rect ÷ offsetWidth`（画面上の大きさ ÷ レイアウト上の大きさ）。

| 見たこと | 結果 |
|---|---|
| サムネ | 10枚すべて **2.000**（158×116px） |
| 詳細 / ⤓ / ✕ / ＋配置 | 10枚すべて **1.000**＝等倍（30×18 / 18×18 / 18×18 / 158×16px） |
| 「＋配置」の帯 | **画像の幅ぴったり（158px）・画像の下端にぴったり**、厚み 16px＝**画像を覆うのは 14%**（前は28%） |
| 詳細 と ⤓ の間隔 / ⤓ と ✕ の間隔 | 74px / 6px＝**重なりなし** |
| 3つのボタンが押せるか | 10枚すべて `elementFromPoint` が自分＝**当たり判定も等倍で正しい** |
| 切り抜き中スピナー | ホバー前後で **13px・border 2px のまま**（回転しても大きさが変わらない） |
| 右パネルからのはみ出し | 10枚すべて **上下左右 0px** |
| ドラッグ中（`.nozoom`） | カードもUIも `transform:none`、`.add` も元の全面オーバーレイ（79×58）に戻る |
| JSエラー | 0件 |

> **ローカルでは楽天APIを叩けない。** `/collect` は `HTTP_REFERRER_NOT_ALLOWED`（403）で必ず失敗する
> ＝楽天アプリの許可リファラが本番ドメインだけ。なので**収集の絡む検証はローカルでは不可能**で、
> カードは `State.furniLib` に item を入れて `renderFurniLib()` を呼んで描かせる（DOM を作るのは
> 本番と同じ `makeFurniEl` なので、幾何の検証としては本番と同一）。**収集そのものの検証は本番で行う。**

### 残っていること

**なし。** 運営の判断（2倍のまま）を受けて push 済み・本番実測済み。
あとから拡大率を変えたくなった場合は、**CSS の `scale(2)` と `zoomOrigin(el, k=2)` の
`k` の両方**を同じ数値にすること（片方だけ変えると、はみ出し判定がずれて端の列が切れる）。

再検証が要るときは `npm i playwright-core` から作り直す（検証スクリプトは一時領域なので
電源OFFで消える）。測る項目は上の表のとおり。**合成 `MouseEvent` では CSS の `:hover` が
発火せず拡大率が 1.000 に見えるので、必ず `page.mouse.move()` で実マウスを動かすこと**
（`transform-origin` を決める JS 側だけは合成イベントでも動くので、気付きにくい）。

### 注意（触る前に読む）

- **クリック＝配置は変えていない。** 拡大は見るためだけの状態で、操作は増やしていない
- **`transform` を使っているのでグリッドは動かない**（周りのカードが逃げない）。
  `width`/`height` を変える実装に置き換えないこと
- **タッチ端末に hover 拡大を掛けないこと。** hover が「タップして残る」挙動になり、
  配置のタップと区別が付かなくなる
