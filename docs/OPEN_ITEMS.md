## ✅ 完了（2026-08-17）— 面から家具に戻すと、家具側の左メニューが既定に戻る

**指摘:** 「家具から面を選択しなおすと、面を選択してた時の左メニューの状態が維持されていますが、
面から家具を選択すると家具が選択されていたときの左メニューがデフォルトの状態に戻っています。
つまり面が選択される前の家具選択時の左メニューの状態を保持し、面から家具が選択された際に
その保持された左メニューの状態にしてください」

**まず何が失われているのか採取した**（家具でいろいろ開く/ONにする → 面へ → 家具へ戻す、の前後で
左メニューの全項目を比較）。**折りたたみグループの開閉は元から維持されていた**（DOM に持っているため）。
失われていたのは次の2つだけ:

| 失われていたもの | 原因 |
|---|---|
| **家具のサブツール**（スポイト / 手で消す / 残す範囲）の ON/OFF とその中身の表示 | `setMode()` が呼ばれるたびに `State.furniEyedrop/furniErase/furniKeep` を無条件で `false` に落としていた。**面側には同じ処理が無い**ので、家具側だけ戻って見えた |
| **左メニューのスクロール位置** | 4つのパネルが1つの `.scroll` を共有していて、モードごとに覚えていなかった。切り替えると直前のパネルの位置をそのまま引き継ぐ（家具で 300 → 面で 250 → 家具に戻ると 250） |

**修正:**

1. `setMode()` からサブツールの `false` 代入を削除し、代わりに **`syncFurniTools()`（新規）で
   State の状態を左メニューへ映し直すだけ**にした。状態の持ち主は State 側。
   描きかけの多角形（`keepPoly.points`）は従来どおり捨てる（面の poly / SAM と同じ扱い）。
   **他モードでフラグが立ったままでも安全**なことは確認済み — これらを読む箇所は
   すべて `State.mode==='furniture'` の内側（描画・ポインタ・contextmenu・キー処理の4か所）。
2. カーソルの決定にサブツールを足した（家具モードでスポイト/残す範囲がONなら `crosshair`）。
   面モードへ出ている間は `crosshair` を外し、戻ってきたら復帰する。
3. **`PANEL_SCROLL`（新規）でモードごとのスクロール位置を記憶。** `setMode` の入口で出ていく側を
   保存し、最後に戻ってきた側を復帰する。**復帰は `requestAnimationFrame` で次フレームに回すのが要点** —
   `setMode` の直後に呼ばれる `syncPanels()` が「選択中の詳細」を出し入れして中身の高さを変えるので、
   同期的に戻すとまだ短い高さに合わせて切り詰められてしまう。

**実測（家具で「手で消す」ON・切り抜き/色のグループを開く・スクロール300 → 面へ移って面側もいじる → 家具へ戻す）**

|---|---|---|
| 「手で消す」のON | **false に戻る** | **true のまま** |
| 「手で消す」の設定ボックス | **閉じる** | **開いたまま** |
| 「切り抜き」「色を変える」グループの開閉 | 維持（元から） | 維持 |
| **左メニューのスクロール位置** | **300 → 250**（面側の位置を引き継ぐ） | **300 → 300** |
| 家具→面→家具 の差分 | 上記が失われる | **家具側の項目は差分ゼロ**（面側のグループ開閉だけが変わる＝面でいじったぶん） |

## ✅ 完了（2026-08-17）— 面を選択している間、選んだ色や素材が水色に隠れて見えない

**指摘:** 「追加された面の色や素材を変えるとき、面を選択すると薄い水色が選択された色や素材の上に
重なっているため、選択された色が選択を解除するまで見えない問題があります。色や素材の選択時に
色がわかるように面の選択時に表示される水色は外してください」

**原因:** `rebuildMaskPreview()` が選択範囲**の全画素**を `rgba(59,111,224,.27)` で塗っていた。
色を選んでいる間ずっとその水色が上に乗るので、実際の色が確認できない。

**修正:** 塗りつぶしをやめ、**輪郭だけを描く**ようにした。
**内側1px＝アクセント色／外側1px＝白**の2色にしてあるので、濃い面でも淡い面でも輪郭が見える。
白は範囲の**外側**に置くので、色を確かめたい範囲の中を隠すのは1pxだけ。

輪郭は選択範囲の外接矩形＋1px の中だけ走査し、`putImageData` もその矩形だけに絞った。
**結果としてコストは下がった**（全画面ぶんの `ImageData` を作って全面に置く必要がなくなったため）。

`drawFacePill`（重心に出る「表面1」のラベル）はそのまま。どの面を選んでいるかはこれで分かる。

**ブラシで塗っている最中は、従来どおり塗りつぶしの即時フィードバックが出る**
（`paintAt` が `maskPreviewCanvas` に円を直接スタンプしているため）。指を離した時点で輪郭に切り替わる。
塗っている最中は範囲を見たいので、この使い分けは意図どおり。

**実測（平坦な部屋に面を作り、カラーピッカーで `#be4855` を指定。同じ色で変更前後を比較）**

「見える色」＝ステージの色にオーバーレイをアルファ合成した結果（＝画面に出る色）を計算した値。

| 選択プレビューが範囲を覆う割合 | **100%**（109,620px 全部） | **1.23%**（1,348px＝輪郭だけ） |
| 面ラベルのピルも含めた覆い | 100% | 3.05% |
| **面を選択したまま見える色** | **`#9a527b`**（水色が乗って紫に化ける） | **`#be4855`**＝**指定した色そのまま** |
| 選択を解除したとき見える色 | `#be4855` | `#be4855`（変わらず） |

| `rebuildMaskPreview` のコスト（1100×825・選択32万px） | 4.88ms | **4.30ms**（わずかに速い） |
| JSエラー | 0件 | 0件 |

**push 後に本番（roomstudio.jp）で同じ検証を回し、上の全項目一致を確認済み**

**素材（マテリアル）についても同じ。** オーバーレイは下に何が描かれているかに関係なく被さるので、

## ✅ 完了（2026-08-17）— 余白を元に戻すと手動で消した背景が戻ってしまう

**指摘:** 「配置した家具の余白を切り詰めた後に手動で背景を消し、余白を元に戻すと、手動で消した
背景まで戻ってしまいます」

**原因:** `layer.eraseMask`（手動消しの記録）を **crop 空間（`natW×natH`）で持っていた**。
crop が変わるとマスクの大きさが合わなくなるので、`untrimFurniture()` は remap できず
`layer.eraseMask=null` で**捨てていた**（当時のコメントも「crop 空間の eraseMask は無効になるので破棄」）。

**逆の順序でも同じ症状が出ていた。** 「消す → 切り詰める → 戻す」でも消した所が戻る。
`trimFurnitureToContent()` はマスクを新しい crop へ切り出し直していたので、
切り詰めで外に出た部分は捨てられ、戻したときに復活していた。

**修正:** マスクを **原寸（`fw×fh`＝AI切り抜き済みならそのキャンバス）空間で持つ**ようにした。
crop は「窓」でしかなくなるので、crop をどう動かしても消した記録は生き続ける。

| 場所 | 変更 |
|---|---|
| `rebuildFurniture()` | マスクを crop の窓だけ読んで適用（`m[(cr.y+y)*fw + cr.x+x]`） |
| `furniFullSize()`（新規） | 原寸の取得を1か所に |
| `normalizeEraseMask()`（新規） | **旧データの移行。** `crop` 空間で保存された作品を開いたら、初回の再構築で原寸へ広げる |
| `ensureEraseMask()`（新規） | 書き込み用に原寸マスクを用意（無ければ作る・旧データなら移行） |
| `eraseFurnitureAt()` / `keepPolyApply()` | crop 局所で出した座標に `+cr.x`/`+cr.y` して原寸マスクへ書く。座標を使う前に `dirty` なら再構築して `natW/natH` を crop と一致させる |
| `trimFurnitureToContent()` | マスクの切り出し直しを**削除**（触らなくてよくなった） |
| `untrimFurniture()` | `eraseMask=null` を**削除**（捨てない） |

判定は「元画像の不透明矩形のうち、いま透明になっている画素数」。crop が変わっても同じ基準で比較できる。

## ✅ 完了（2026-08-17）— Escape で選択を解除する

**依頼:** 「配置されたオブジェクトが選択時にエスケープボタンが押された際も選択が解除される
ようにしてください」

**修正:** `document` の `keydown` に1行足した。**置く位置が重要で、既存の「作図中」ブロックより後**
（`Delete`/`Backspace` の削除より前）に入れてある。

```js
if(e.key==='Escape' && !typing && State.selectedId!==null){ e.preventDefault(); deselectAll(); return; }
```

- **`typing` の判定を入れている理由:** 入力欄（`INPUT`/`TEXTAREA`/`SELECT`・`contentEditable`）に
  フォーカスしているときの Escape で選択が消えると、文字を打っている最中に選択を失う。
- **作図中ブロックより後に置く理由:** 多角形（表面の `poly`・家具の「残す範囲」）を描いている途中の
  Escape は**打った点の取り消し**に使われる。先に置くと点が消せなくなる。あちらは `return` するので、
  作図中は選択に届かない。

**対象は家具・表面の両方。** 依頼文は「配置されたオブジェクト」だが、`deselectAll()` は選択を外すだけで
何も壊さないので、種類で分けていない。家具だけに絞りたい場合は言ってもらう。

**実測（部屋を読み込み → 家具2つを配置 → 表面レイヤーを追加）:**

| 場面 | 結果 |
|---|---|
| 家具を選択 → Escape | `selectedId` **2 → null**、レイヤー行のハイライト解除、家具詳細パネル→未選択、オーバーレイの不透明ピクセル **7,680 → 0px** |
| **レイヤーが消えていないか** | **`State.layers` は 2件のまま**（`Delete` と違って削除はしない） |
| 何も選択していないときに Escape | 何も起きない・エラーも出ない |
| 表面レイヤーを選択 → Escape | `selectedId` **3 → null** |
| **回帰: 多角形を3点打った直後の Escape** | **点が 3→0 に消え、選択は 3 のまま維持**。もう一度 Escape で選択が解ける（＝優先順が意図どおり） |

## ✅ 完了（2026-08-17）— 非表示にしたレイヤーの選択が残る

**指摘:** 「配置されている家具をクリックし、選択した状態で非表示ボタンを押しても

```js
on(eye,'click',ev=>{ ev.stopPropagation(); l.visible=!l.visible;
  if(!l.visible && State.selectedId===l.id){ deselectAll(); return; }
  renderLayers(); render(); });
```
