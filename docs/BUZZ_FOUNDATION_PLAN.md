## 判断の記録

### なぜアプリ本体を読み込まずに別ページにしたか

`room-studio.html` は **319KB・3,933行（うちJS 2,985行）** の単一ファイルで、SAM（ONNX
セグメンテーション）・LaMa補完・楽天収集・レイヤー・undo/redo が `State` を共有して
一体化している。読み込むだけで §1 の性能目標（初回表示3秒）に届かず、部分的に読む
分割もできない。よって **LPと同じ流儀で `api/_site.py` に独立ページを生成**した。
アプリ本体には一行も触れていないため、リグレッションが構造的に起きない。

### 面（壁・床）の指定を固定ポリゴンにした理由

本体はブラシ／SAM／ポリゴンで毎回ユーザーに面を選ばせるが、`/try` にその操作は不要。
**部屋ごとに 0..1 の正規化ポリゴン座標をコードに固定で持つ**方式にした。

- マスク画像を配信する案より軽い（座標は数十バイト）
- 運営が用意するのは**写真1枚だけ**で済む（マスク作成は現実的でない）
- 実寸に依存しないので、写真を差し替えても座標の意味が変わらない

### 再着色は「移植」ではなく最小の再実装

本体 `rebuildSurface()` は素材バッファ・透視変換・遮蔽レイヤーまで抱えており、
`/try` に必要なのは色替えだけ。**色相・彩度は目標色に置き換え、明度は面全体を目標色の
明るさへ寄せるオフセットだけかける**方式を約60行で書いた。ピクセルごとの明暗差
（木目・陰影・光のむら）は残るのでベタ塗りにならない。

明度オフセットは実装途中に**必要と分かって追加**した。当初は明度を完全に保持していたが、
それだと「ウォルナット」のような暗い色を選んでも床が暗くならず（実測 205→205）不自然だった。
オフセット導入後は 201,189,168 → 164,133,104 と正しく暗くなる。

### `/try` は sitemap に載せる

SNSからの着地ページであり、通常どおり公開・インデックスされるべきもの。
運営専用の `/demo` は §2 で `noindex` ＋ sitemap 非掲載にする（別扱い）。

### §3 の方針（運営決定・2026-07-29）

**楽天由来の家具レイヤーを除外して書き出す**（書き出し停止ではない）。理由は、
壁・床の色変更の before/after だけでも拡散素材として十分機能するため
（色の変化こそが視覚的に映える要素であり、家具の有無は拡散力にほぼ影響しない）。

- 除外時はユーザーに「共有画像には家具は含まれません」と簡潔に表示する
- 実装コメントに、この判断の理由と楽天規約の該当箇所を明記する

根拠となる規約の該当箇所は `docs/LP_IMAGE_GUIDE.md` §🔴 と
`rakuten-application-info.md`（目的外利用しない／再配布しない／不特定多数と
共有可能な場所へ保管しない）。

### 商品リンクについて（運営の対応が必要）

指示書は「使用した家具の商品リンクを1〜2件表示」としているが、楽天の商品は実行時に
APIで取得するものでURLを固定できず、`/try` で在庫・価格の変動する商品を
ハードコードするのは不正確になる。また `/try` の家具はプレースホルダであり、
楽天の商品ではない。

そこで **`api/_site.py` の `TRY_PRODUCTS` に運営が実在の商品を1〜2件入れるとブロックが
出る**形にした（空ならセクションごと非表示）。形式は
`{"title": ..., "url": <アフィリエイトURL>, "shop": ...}`。
クリック時は既存の `/track` と GA4 `select_item` に流れる。
