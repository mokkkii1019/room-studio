## 5. ★ やってはいけないこと（地雷集）

今回の調査で実際に踏んだ／踏みかけたもの。**ここを読まずに設定を触らない。**

| | 禁止事項 | 理由 |
|---|---|---|
| 1 | **内部トラフィック定義のIP範囲を広げない**（`/32` のまま） | `126.x` はSoftBank系で光もモバイルも同じ帯域。`/24` や「次で始まる」にすると**赤の他人が除外される**。データフィルタで落ちたデータは**復元できない** |
| 2 | **データフィルタを「含める」にしない** | 内部トラフィック以外が全部捨てられる。復元不能 |
| 3 | **LP→アプリの内部リンクにUTMを付けない** | GA4がセッションを切り直してキャンペーンを上書きし、流入元が丸ごと消える。内部導線は `ref=` を使う（`docs/MEASUREMENT.md` §6-3） |
| 4 | **`GA4_INTERNAL_TRAFFIC=1` のままフィルタを無効にしない** | 自己クリックが素通しになる（同 §7-3） |
| 5 | **`utm_medium` に媒体名を入れない**（必ず `social`） | 既定チャネルグループから外れて Unassigned に落ちる（同 §6-2） |
| 6 | **疎通確認のキャンペーン名を使い回さない** | `probe-0808` を2回の別テストで再利用して混ざった。`probe-YYYYMMDD` で毎回変える |
| 7 | **素の数字をそのまま報告しない**（必ず `--jp`） | 4割強が海外の自動巡回。ユーザー数は実態の3倍、エンゲージメント率は実態の6割に見える（§11-2） |
| 8 | **ボットを GA4 のフィルタで除外しない** | そもそも地域では除外できないうえ、落としたデータは復元不能。米国31件のうち1件は `fbclid` 付き＝本物の可能性がある（§11-4） |
| 9 | **「本番ドメイン以外は全部リダイレクト」にしない** | プレビュー配信が本番へ飛んで**動作確認ができなくなる**。旧ドメインだけを名指しする（§11-7） |

## 6. ★ 運営端末でのテスト方法（間違えやすい）

**フィルタが「有効」の今、運営自身の端末はリアルタイムに絶対に出ない。これは正常。**
「出ない＝壊れている」と誤読して調査に半日かかった。判定は**2条件の組み合わせ**で行う。

| | 運営端末（除外対象） | 外部ユーザー |
|---|---|---|
| GA4 リアルタイム | **出ない（正常）** | 出る |
| **GA4 DebugView** | **出る**（← ここで確認する） | 出ない |

- 端末の除外フラグを見る: ブラウザのコンソールで `localStorage.rs_notrack`（`'1'` なら除外対象）
- その端末がIPで internal 判定されているかは、**`gtag.js` を開いて `__ogt_ip_mark` と `macros` を読む**（`docs/GA4_ACCESS_REPORT.md` §10-3）
- どうしても切り分かないときは、**データフィルタを一時的に「テスト」にする**（同 §10-4）。
  除外されずに `testDataFilterName` 付きで記録されるので、DataAPI から観測できる。**終わったら必ず「有効」に戻す**
