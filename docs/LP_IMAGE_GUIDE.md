# LP 画像ガイド（運営者が用意する画像）

LPに「画像スロット」を実装済み。**ファイルを `lp-assets/` に置くだけ**で自動的に表示されます。ファイルを置くと、その枠が自動で表示されます（before/afterは2枚そろったときだけ表示）。

- **ヒーロー(A)**: **動画 → 写真 → SVGイラスト** の順に、置いてあるものが自動で使われます。何も無い間は**インラインSVGの室内イラスト**（明らかにイラストと分かる装飾。写真や「実例」を騙らない）が出るので、空箱にはなりません。ヒーローは**画面幅いっぱい**に出ます。→ 動画の置き方は下の「ヒーロー動画」を参照。
- **before/after(B)**: 実キャプチャの真正性を守るため**画像のフォールバックはなし**（ダミー画像やフリー素材で代用しない）。現行LPは `ph: True` なので、未配置の間は「Before画像が入ります／…」と書かれた**破線のプレースホルダ枠**を表示します。枠のサイズは実画像と同一なので、あとからファイルを置いてもレイアウトは動きません。`api/_site.py` のLPから `"ph": True` を外すと、2枚そろうまで**セクションごと非表示**に切り替わります。

### 🏠 ヒーロー画像は「変わる前のふつうの部屋」にする（2026-07-28 方針変更）

ヒーローは**画面幅いっぱい・画面の高さの78%**で表示され、その上に白文字で見出しが乗ります。

**主役は「完成された理想の部屋」ではなく「変わる前のふつうの部屋」です。**
H1が「集めた画像は、自分の部屋じゃない」と言っているのに、完成された北欧の理想部屋を
出すと矛盾します。「**あなたのその部屋を変えられる**」と伝わる画像にしてください。

| 条件 | 内容 |
|---|---|
| ✅ 様式 | **特定のテイストが判別できない**（北欧/ナチュラル/インダストリアル等に寄せない） |
| ✅ 色 | **木質・白basedに寄りすぎない**。特定トーンの完成形に見せない |
| ✅ 光 | **明るく、自然光が入っている**（暗い・重い部屋はNG） |
| ✅ 家具 | **最小限か、無し**。作り込まれたコーディネートにしない |
| ✅ 生活感 | **ありすぎない**（散らかっている必要はない。無人・生活痕は控えめ） |
| ⚠️ 構図 | **被写体を中央に寄せる**。モバイルでは左右が切り取られます |

**現在置いてある `moyougae-simulation-hero.webp` は差し替え対象**です（白壁＋ライトオーク、
細脚のローボード、テラコッタのプフ等、北欧/ナチュラルの完成形）。ただし**新しい画像を置くまでは
現画像がそのまま表示される**ので、LPが空になることはありません。**同じファイル名で上書き**すれば
自動的に切り替わります。

### 🎬 ヒーロー動画（NOT A HOTEL のような全面動画にする場合）

`lp-assets/` に **`moyougae-simulation-hero.mp4`** を置くと、ヒーローが自動で全面動画になります
（写真より動画が優先）。ミュート・ループ・コントロール無しの「雰囲気を出すための背景動画」
として再生されます。

| 項目 | 指定 |
|---|---|
| ファイル名 | `moyougae-simulation-hero.mp4`（必須）／`moyougae-simulation-hero.webm`（任意・あれば優先して使われます） |
| 比率・実寸 | 16:9 / 1600×900 px 前後（1920×1080 でも可） |
| 長さ | **6〜12秒のシームレスループ**（つなぎ目が目立たないもの） |
| 音声 | **必ず削除**。ミュート再生が前提なので、音声トラックは容量の無駄です |
| **容量** | **3MB以下**（重要。理由は下記） |
| コーデック | H.264 (mp4) / VP9 (webm)。`-movflags +faststart` 相当でメタデータを先頭に |

⚠️ **静止画も必ずセットで置いてください。** `moyougae-simulation-hero.webp` が動画の
**poster（表紙）**として自動で使われ、次の場面で表示されます。動画の1コマを書き出すのが理想です。

- 動画の読み込みが終わるまでの最初の表示（ページの体感速度を決めるのはここ）
- ブラウザが自動再生を拒否したとき（省データモード等）
- OSで「視差効果を減らす／アニメーションを減らす」を有効にしている人（**自動再生しません**）

⚠️ **3MB以下にする理由**: 現在この構成では動画も Python の関数経由で配信しており、
Vercel の1レスポンス上限（約4.5MB）があります。安全のため1レスポンスを3MBで区切る
実装（HTTP Range対応）にしてあるので、これを大きく超える動画は読み込みが重くなります。
どうしても大きな動画を使いたい場合は、Vercel Blob などの外部配信に切り替える必要があります（未対応）。

🚫 ライセンスは写真と同じ。**人物・ブランドロゴ・他社商品が写った動画は使わない**、
商用利用可・帰属表示不要の素材のみ。

### before/after は「ドラッグ比較スライダー」になります

**2枚そろったときだけ**、before と after が1枚に重なり、**ハンドルを左右に動かして境目を動かす**表示になります（キーボード操作にも対応）。ファイル名・比率・推奨サイズは今までと同じなので、**書き出し直しは不要**です。

- 2枚そろっていない／JavaScript が無効 → **従来どおりの横並び2枚**に自動フォールバック（崩れません）
- そのぶん **before と after は「まったく同じ画角」で撮ることが重要**です。画角がずれていると、重ねたときにガタつきます

- 置き場所: リポジトリ直下の **`lp-assets/`**
- 配信URL: `https://roomstudio.jp/lp-assets/<ファイル名>`（`/lp-assets/{name}` ルートが配信）
- **対応形式**: `.webp`（推奨）/ `.jpg` / `.jpeg` / `.png` / `.avif`。**拡張子は自動判別**（例 `moyougae-simulation-hero.jpg` を置けば `moyougae-simulation-hero` のスロットに入る）
- 置いたら `git add lp-assets/ && commit && push`（main反映で本番に出る）

## ⚠️ ライセンス注意（必読・厳守）

**要点2つ:** ①ヒーロー(A)のフリー素材ルール（下記）、②before/after(B)に**楽天収集家具を写さない**（さらに下）。

ヒーロー写真（下記A）は**フリー素材**を使います。必ず以下を守ってください。

- ✅ **商用利用可・帰属表示不要**の素材のみ（例: Unsplash / Pexels の標準ライセンス）。
- 🚫 **人物が写った写真は使わない**。モデルリリース（肖像の使用許諾）はフリー素材側で保証されません。**無人の室内・インテリアに限定**。
- 🚫 **ブランドロゴ・商標・他社商品が明確に写った写真は使わない**。
- 🚫 **Unsplash等のAPI経由で自動取得しない**。API利用は帰属表示が必須になる等、条件が変わります。**手動でダウンロードした静的ファイル**を置いてください。
- 🚫 フリー素材写真を「Room Studioで加工した実例」であるかのように見せない（それは下記Bの役割）。ヒーローは**あくまでイメージ写真**。

### 🔴 before/after に「収集した家具」を写してはいけない（楽天規約）

before/after（下記B）は Room Studio で作ってキャプチャしますが、**権利がクリアなのは
「あなた自身の部屋写真＋CC0の壁・床素材」だけを写した場合に限ります。**

**楽天から収集した家具を配置したキャプチャをLPに載せてはいけません。** LPは公開ページ＝
「不特定多数と共有可能な場所」であり、そこへ楽天の商品画像（を合成した画像）を置くことは、
楽天ウェブサービス利用規約に反します。当アプリの登録申請でも「目的外利用しない／再配布
しない／不特定多数と共有可能な場所へ保管しない」と明記しており（`rakuten-application-info.md`）、
LP掲載はこのいずれにも抵触します。画像は `/imgproxy`・`/bgcut` とも保存しない方針です。

before/after のAfterに家具を写したい場合は、**楽天以外の権利がクリアな家具**に限ります:

- ✅ あなたが撮影した／所有している家具の写真をアップロードして配置
- ✅ CC0・商用可ライセンスの家具画像
- ✅ **壁・床の素材（CC0のambientCG）や配色だけを変えた**キャプチャ（家具を置かない）
- 🚫 「家具を収集」機能で楽天から取り込んだ家具を配置したキャプチャ
- 🚫 どうしても楽天商品を使うなら、楽天ウェブサービス／該当店舗から**書面の許諾**が必要

なお現行LPのAfterは**壁・床の変更のみ**の指示なので、そのとおりに作ればクリア。

### 高DPR対応（2026-07-30）

before/after は全幅バンドで出るため、**DPR2 のデスクトップでは 1600px 素材が 1.8〜2.4倍に
引き伸ばされ**、粗さが見えていた（1920幅/DPR2 で必要 3840px）。対策として:

1. `tools/fit_lp_image.py` に **`--also-2x`** を追加し、`<スロット名>-2x.webp`（1.5倍 =
   2400×1350）も書き出せるようにした。画素数が増えるぶん圧縮アラが目立たないので
   quality は 86 から始め、**1x とほぼ同じ重さ**（215KB / 238KB）に収まっている
2. **拡大時のみ**アンシャープ（radius 1.0 / 70% / threshold 3）を掛ける。縮小時は掛けない
3. `_img()` が `-2x` の存在を見て **`srcset` + `sizes="100vw"`** を出す

実測でどの端末が何を取るか:

| 端末 | 取得ファイル | 合計 |
|---|---|---|
| デスクトップ DPR1 / **スマホ DPR3** | 1x（174KB + 199KB） | 574KB |
| Retina ノート・デスク DPR2 | **2x**（215KB + 238KB） | 654KB |

**スマホは 1x のまま**（390css × DPR3 = 1170px ≤ 1600px）なので、重い方は必要な端末しか
取りません。画面上のシャープさは修正前比で +22%。

⚠️ **before と after は必ず同じ引数で作り直すこと**（トリミング・シャープ・実寸すべて）。
片方だけ作り直すとスライダーがガタつきます。作り直し後のずれ実測は 1x で dx0.010/dy0.012、
2x で dx0.007/dy0.008、1x と 2x の画角差は dx0.018/dy0.001 でした。

**再検証（2026-07-29・完成品どうしの実測）**: 配置後の before/after 2枚を直接突き合わせ、
位相相関で全体のずれを測ったところ **dx 0.016px / dy 0.001px**（エッジのみでも dx 0.007px /
dy 0.012px）で、スライダーがガタつく水準ではありません。差分マップでも変化は壁と床に集中し、
窓ガラス（木の眺め）と天井はほぼ無変化であることを確認しています。

**次に作り直す場合は、下記の手順どおり before ファイルそのものを読み込んでください**
（原本を読み込むとトリミングの当て直しが必要になります）。

## 配置のコツ
- WebP変換とリサイズは [Squooss](https://squoosh.app/) 等で。横1600px・品質75前後で十分きれいかつ軽量。
- before/after は**同じ画角・同じ部屋**で撮ると対比が伝わります（Room Studioの「比較」機能でスクショしてもOK。ただし**楽天収集家具は写り込ませない**——上の🔴）。
- alt文言はコード側に実装済みなので、ファイルを置くだけで差し替わります（変更したい場合は `api/_site.py` のLPの `hero`/`ba` の `alt` を編集）。
